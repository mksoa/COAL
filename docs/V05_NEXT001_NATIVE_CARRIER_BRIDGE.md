# COAL native carrier object bridge — source-only successor

This extends V0.4 without activating the COAL custodian or NEXT-001. The **six original** GLOW R12 operation strings are the only supported object-carrier operation identifiers. A deterministic single-file COAL Git tree binds exact original PRE-ACT, target blob/path, operation-binding digest and explicit current source successor. It MUST NEVER replace COAL `main`.

`GitHubCarrierObjectWrite` requires an externally injected writer and token provider; `GitHubCarrierObjectRead` is a separate read transport. `prepare_native_carrier_once` calls native `POST /git/blobs`, `POST /git/trees`, `POST /git/commits` **once each, in order** after exact caller plan verification. Each original POST ACK is returned as a protected receipt. Any missing/ambiguous/divergent ACK stops before the next POST; no retry/refund. After commit ACK, it GETs the blob, nonrecursive tree and commit through the separate reader; exact content, SHA, tree entries, parent and message must agree. Any read failure is nonpositive. These Git objects do **not** create an attempt ref, consume any of the six original NEXT-001 effects, establish a credential issuer, issue H0/M0 or qualify W038.

The remaining operational slices are a **narrow, six-whitelisted, custodian-controlled distributed one-use admission**, original native acknowledgement/readback, outside independently administered W038 evidence, and the actual GLOW resident source/H0/JIT M0/Claim→Slot qualification. The historic R-J evidence is not reused as such proof. Do not wire this source adapter into CLI, CI, or an owner-H0 trigger before that scope is independently constituted. No new workflow, release, campaign or generic code executor is introduced here.

Source review correction: native original POST/GET receipts use UTC observation timestamps; native Base64 content permits GitHub line wrapping while preserving exact decoded blob hash/length. Positive source-level shape is NOT authenticated custody or an actual native run.

Identity correction: only subject `NEXT-001`, epoch equal to the immutable original PRE-ACT commit, and the six frozen original operation IDs are accepted by the native object bridge. This constrains carrier derivation but does NOT establish that a future external one-use admission is keyed by the original operation ID across successor digests. Such an independent six-key allowlist must be qualified before any runtime ref CREATE.
